# M1 : noyau (`dev` → `main`)

Module `core` neuf (couche 0 de `docs/03`), sans aucun appel graphique : erreurs, mémoire, tâches, profilage, configuration, temps, événements, maths à double précision, ressources à handles, système de fichiers virtuel, sérialisation avec réflexion, observateur de fichiers. Le logger existant est conservé et testé. Archive `libcore.a`, en-têtes `include/engine/core/`, sources `src/core/`, tests `tests/core/`. Description des fichiers : `src/core/README.md`.

## Commande de démo

```bash
make core-demo                                              # 10 000 tâches, configuration rechargée à chaud, mesures
make core-demo CORE_DEMO_ARGS="--help"                      # réglages
make core-demo CORE_DEMO_ARGS="--tasks 50000 --trace t.json"   # trace à ouvrir dans https://ui.perfetto.dev
```

Résultat (`docs/BASELINE/core-demo-M1.txt`) : 10 000 tâches sur 21 fils, somme de contrôle exacte ; le fichier de configuration modifié pendant l'exécution est repris (`config.name`, `config.octaves`) ; 6 images, 6 pas fixes de 10 ms.

## Limites connues

- Windows et macOS : jamais exécutés par moi ; la CI du push les exercera (G28). `FileWatcher` (CORE-13) reste `Partiel` jusque-là.
- CORE-02, CORE-05 restent `Partiel` (exceptions héritées G51 ; minuteries GPU via le RHI G54).
- Rien du moteur n'utilise encore `Config`, `Vfs`, `ResourceCache` ni `WorldPosition` : branchement en M2/M3 (G52, G53). Aucun comportement existant n'a changé, sauf A12 (graine explicite).
- `Logger::Initialize` lève une exception si le dossier du journal est impossible à créer (G50).
