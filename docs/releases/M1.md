# M1 : noyau (`dev` → `main`)

Module `core` neuf (couche 0 de `docs/03`), sans aucun appel graphique : erreurs, mémoire, tâches, profilage, configuration, temps, événements, maths à double précision, ressources à handles, système de fichiers virtuel, sérialisation avec réflexion, observateur de fichiers. ## Commande de démo

```bash
make core-demo                                              # 10 000 tâches, configuration rechargée à chaud, mesures
make core-demo CORE_DEMO_ARGS="--help"                      # réglages
make core-demo CORE_DEMO_ARGS="--tasks 50000 --trace t.json"   # trace à ouvrir dans https://ui.perfetto.dev
```

Résultat (`docs/BASELINE/core-demo-M1.txt`) : 10 000 tâches sur 21 fils, somme de contrôle exacte ; le fichier de configuration modifié pendant l'exécution est repris (`config.name`, `config.octaves`) ; 6 images, 6 pas fixes de 10 ms.

## Limites connues

- Windows et macOS : jamais exécutés par moi ; la CI du push les exercera (G28). `FileWatcher` (CORE-13) reste `Partiel` jusque-là.
- CORE-02, CORE-05 restent `Partiel` (exceptions héritées G51 ; minuteries GPU via le RHI G54).
- Rien du moteur n'utilise encore `Config`, `Vfs`, `ResourceCache` ni `WorldPosition` : branchement en M2/M3 (G52, G53). Aucun comportement existant n'a changé, sauf A12 (graine explicite).
- `Logger::Initialize` lève une exception si le dossier du journal est impossible à créer (G50).

## CI du push et revue CodeRabbit (PR #5)

CI du push `e992044` : Linux, ASan/UBSan et macOS verts ; **Windows rouge** (un seul cas : le test d'export Chrome trace gardait un `ifstream` ouvert avant `remove`, que Windows refuse ; corrigé, Windows vert sur `68c3bb7`). La PR comptait 345 fichiers (M0 squashé dans `main` + M1) : CodeRabbit, limité à 300, ne relisait rien ; `dev` a été resynchronisé avec `main` (`git merge -s ours`, arbre inchangé), la PR passe à 69 fichiers (`docs/06` §3 interdit désormais le squash pour `dev` → `main`).

CodeRabbit : 18 commentaires en ligne + 17 mineurs. Tout ce qui touchait du code de M1 a reçu un test qui échoue avant la correction (vérifié avec l'ancien code) :
