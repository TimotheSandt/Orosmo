# M3 : premier générateur de terrain et interface de base (lots A à F)

Première release présentée comme **utilisable** (numéro proposé : `v0.3.0`, `mk/config.mk` ; l'étiquette est posée par l'auteur).
Plan et découpage : `docs/05` (lots A à F, A29). Guide d'utilisation : `docs/USING_THE_ENGINE.md`.

## Ce qui a changé, par lot

| Lot | Contenu | Branches |
| --- | --- | --- |
| A | Module `engine::world` : bruit **déterministe** (Perlin, Simplex, Worley, fBm, distorsion) sur hachage entier et opérations IEEE de base, `-ffp-contract=off` partout ; sommes de contrôle de référence | `feat/TER-01-noise` |
| B | Tuiles (positions depuis des indices entiers globaux), quadtree équilibré à bords cousus, `TileStreamer` (tâches, budget mémoire, éviction) | `feat/TER-02-tiles-lod` |
| C | Repère Vulkan du RHI (A26 : `glClipControl`, origine en haut, profondeur 0..1), caméra reverse-Z à plan lointain infini et rendu relatif à la caméra, `DebugDraw`, `TerrainRenderer` (pente/altitude, triplanaire, tableau de textures), bruit sur GPU égal au CPU | `feat/REN-02-vulkan-frame`, `feat/REN-34-debug-draw`, `feat/TER-07-terrain-render`, `feat/TER-01-gpu-noise` |
| D | Export (PNG 16 bits, EXR, OBJ, glTF, STL fermé, biomes), lancer de rayon, `terrain-gen` | `feat/TER-11-export`, `fix/asan-array-bounds` |
| E | Module `engine::ui` (thèmes JSON à jetons et états rechargés à chaud, widgets, mise en page, entrées, événements nommés, paramètres réfléchis) ; compilateur du langage vers `engine::ui` (liaisons `$`, erreurs `fichier:ligne:colonne`, `#line`) ; `docs/UI_LANGUAGE.md` ; visualiseur avec panneau `.cui` ; saisie de texte | `chore/UI-move-legacy-src`, `feat/UI-07-themes`, `feat/UI-03-widgets`, `feat/UI-05-cui-engine`, `feat/TOOL-01-viewer` |
| F | Paquet complet (shaders, police, thèmes, exemples), `orosmo init --package`, test de bout en bout `make e2e-init`, `docs/USING_THE_ENGINE.md`, projet minimal | `feat/BLD-02-package-e2e`, `docs/DOC-01-using-the-engine` |

Identifiants (`docs/STATUS.md`, « M3 ») : **Fait** TER-01, TER-02, TER-03, TER-07, TER-11, TER-12, TER-13, TOOL-02, REN-02, REN-34,

## Changements incompatibles (par rapport à M2)

| Changement | Effet | Migration |
| --- | --- | --- |
| Repère du RHI (A26) | ligne 0 d'une texture = haut ; NDC y = +1 en haut ; profondeur [0, 1] | lecture de pixels sans retournement ; projections `glm` en `_ZO` ; `glClipControl` requis (OpenGL 4.5 ou `GL_ARB_clip_control`) |
| Caméra reverse-Z | profondeur effacée à 0, test `kGreater` ; plan lointain infini par défaut | `SceneRenderer` le fait ; un pipeline maison doit suivre (`docs/RHI.md`) |
| `DrawRect` | champs `radius`, `borderWidth`, `borderColor`, `softness` ajoutés | une initialisation agrégée positionnelle reste valide (valeurs par défaut) ; préférer les initialiseurs désignés |
| `src/UI/` → `src/ui/legacy/` | chemins des sources de l'interface héritée | aucun pour un utilisateur (les en-têtes `include/UI/` ne bougent pas) |
| `cui` | messages d'erreur `fichier:ligne:colonne: error: …` ; l'en-tête généré porte le nom du **fichier** (`st.cui` → `st.gen.h`) ; rien n'est écrit pour un source invalide ; JSON de `check` avec `file` | un `#include` du nom de la vue quand il diffère du fichier est à corriger |
| `InputManager` | la position de la souris est maintenant juste (elle était corrompue par l'écriture de `double` dans des `float`, G115) | — |

Stabilité : `core`, `rhi`, `renderer`, `world`, `ui` figés pour 0.3.x ; `platform` provisoire (A31, G105).

## Nettoyage et nom Orosmo (2026-11-20, après la revue)

À la demande de l'auteur : le projet s'appelle **Orosmo** et les modules hérités sont retirés. Branches `chore/cleanup-*`.

| Changement | Branche |
| --- | --- |
| `Logger` → `engine/core/log.hpp`, `GET_RESOURCE_PATH` et chemins → `engine/core/paths.hpp` ; `Utilities` supprimé (`lerp`, `rotate`, doublons de `core::system`) | `chore/cleanup-core-logger` |
| `Profiler`, `FPSCounter`, `RingBuffer`, `IGpuTimer` → `engine/core/` (namespace `engine::core`) | `chore/cleanup-core-profiler` |
| `Benchmark` → `engine/core/benchmark.hpp` (`engine::core::bench`, noms en `camelCase`), 8 tests ajoutés | `chore/cleanup-benchmark` |
| Interface héritée `include/UI/`, `src/ui/legacy/` et cible `UI::View` du compilateur `cui` supprimées (`OUTPUT_FORMAT_VERSION` 9) ; `TextRenderer` → `engine/ui/text_renderer.hpp` ; panneau de performances de la démo sur `engine::ui` (thème `res/themes/hud.json`) | `chore/cleanup-legacy-ui` |
| Terrain de la démo sur `engine::world` (streaming autour de la caméra) ; `Noise`, `apps/demo/src/ProceduralGeneration/` et `include/Graphics/` supprimés ; options de lancement dans `apps/demo/src/launch_options.*` ; nouvelle image de référence `scene-opengl-seed1-1280x720.png` (llvmpipe) | `chore/cleanup-demo-world` |
| Nom Orosmo (configuration, outil, SDK, extension VS Code), versions alignées sur 0.3.0, `relief.png` et `rhi-demo.png` retirés du suivi | `chore/cleanup-orosmo` |
| Outil en ligne de commande renommé `engine` → `orosmo` (`orosmo init`, `orosmo update`) ; fichiers de release `orosmo-<plateforme>[.exe]` et `orosmo-pkg-<plateforme>.zip` (A32) | `chore/rename-cli-orosmo` |

**Changements incompatibles** : en-têtes `Utilities/`, `Profiler/`, `Benchmark/`, `Noise/`, `Graphics/`, `UI/` supprimés (inclure
`engine/core/log.hpp`, `engine/core/profiler.hpp`…) ; `Logger`, `Profiler` et leurs types sont dans `engine::core` ; `cui` refuse
un fichier sans `import "engine/ui"` ; extension VS Code publiée sous `orosmo.cui-language` ; l'outil s'appelle `orosmo` (et non plus `engine`), le paquet
`orosmo-pkg-<plateforme>.zip`, et `orosmo update` ne remplace plus un binaire local nommé `engine` (aucun projet extérieur ne
l'utilisait). Le dossier `engine/` d'un projet (le paquet extrait) garde son nom.

**Tests supprimés** (ils ne testaient que le code retiré) : `ui_foundation_tests`, `ui_collect_tests`, `binding_tests`,
`parity_tests` (parité avec l'ancien rendu), `noise_tests` et `procedural_tests` hérités, `utilities_tests` (lerp, rotate). Le job
Linux arm64 qui échouait sur la parité de l'interface n'a donc plus ce test. A32 tranchée (outil renommé, `engine::` et
`include/engine/` gardés) ; nouveaux écarts G119 à G122.
