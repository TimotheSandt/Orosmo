# M9 : macOS et Metal (Vulkan par MoltenVK)

Jalon de `docs/05-PLAN_PAR_JALONS.md`, « M9 · macOS et Metal », sur la branche `milestone/M9` (**pas dans `dev`** tant que M8
n'est pas validé, A90). **Ni version changée, ni tag, ni release.** Découpage en six lots (A90), une PR par lot vers
`milestone/M9`.

**La démo du jalon, « visualiseur sur un Mac », est ABSENTE.** Il n'y a pas de Mac : rien n'a été essayé sur un vrai Mac
(Apple Silicon ou Intel). La seule preuve est la CI macOS (`macos-26`, macOS 26.7.2, machine virtuelle, GPU « Apple
Paravirtual device », MoltenVK 1.4.2 de Homebrew). Les captures du runner ne valent pas un essai : ni fenêtre vue par un
humain, ni saisie, ni écran Retina, ni GPU physique, ni performances. **macOS Intel : le rendu est absent** (tout lancement
s'arrête sur la machine virtuelle de la sonde, G523). Aucun backend Metal natif n'a été écrit.

## Changements d'API et de comportement

- Ajouts : `rhi::Capabilities::validation` et `srgbStorageImages`, `rhi::fallbackBackend`, `rhi::kHostIsMacOS`,
  `rhi::kNoFallbackOnMacOS`. Aucune signature existante changée.
- **macOS** : plus de repli sur OpenGL, ni dans la démo ni dans `app::Application` ; messages et aide en ligne ajustés.
- `Capabilities::timestampQueries` peut être faux sous MoltenVK : `GpuTimer` n'y mesure alors rien.
- Backend Vulkan : transitions d'images 3D sur toute la profondeur ; sous MoltenVK, fonctions de portabilité activées ; sur
  le GPU paravirtualisé, chaque dessin indexé devient une commande indirecte (`ENGINE_VULKAN_INDEXED_VIA_INDIRECT=0|1`).
- SDK : rpaths `/opt/homebrew/lib` et `/usr/local/lib` sur macOS, redéfinissables ; `orosmo doctor` a deux contrôles de plus.
