# v0.6.2 : distribution du SDK (`feat/SDK-integ`)

## Résumé

Décision **A76** de l'auteur (2026-11-25) : le moteur s'installe **une fois par machine**. Un installeur (`install.sh`,
`install.ps1`) installe les paquets système après confirmation, l'outil `orosmo` dans `$OROSMO_HOME/bin` (ajouté au `PATH`) et
le moteur précompilé dans `$OROSMO_HOME/engines/<version>` ; un projet nomme sa version (`OROSMO_VERSION` dans `config.mk`)
au lieu de copier le moteur. Les bibliothèques tierces du moteur sont précompilées dans `deps/` du paquet : **ni vcpkg ni
`make install`** pour le développeur. **Aucun code C++ du moteur touché** ; le jeu livré aux joueurs ne change pas.

## Contenu

- **Paquet** : `deps/{include,lib,licenses}` (statiques, shaderc compris ; jamais le chargeur Vulkan, OpenGL, X11/Wayland ni la libc), fichier `VERSION` (`tools/package-deps.sh`, `make dist`).
- **Construction** : `engine.mk` et `OrosmoConfig.cmake` lisent `deps/` ; la sortie du compilateur `.cui` va dans `Generated/` du projet : rien n'écrit dans le moteur installé. Le `Makefile` du gabarit résout `ENGINE_DIR` : variable donnée, `orosmo/` local, `orosmo path $(OROSMO_VERSION)`, sinon erreur avec la commande à lancer.
- **Outil `orosmo`** : `install` (vérification `SHA256SUMS`, extraction atomique), `list`, `remove`, `path`, `init [--vendor]`, `update`, `migrate` (ancien projet ; `orosmo/` supprimé seulement après un build réussi), `build [--release] [--json]`, `run [-- args]`, `clean`, `self-update`, `doctor [--fix]` (sans vcpkg).
- **`build --json`** : une ligne JSON par événement (`begin`, `end`, `diagnostic`, `done`), pour une future interface graphique.
- **Installeurs et release** : `install.sh`, `install.ps1` et `SHA256SUMS` joints à chaque release (travail parallèle sur la CI).
- **Documentation** : A76 (`docs/QUESTIONS.md`), `docs/03` §16 « Distribution du SDK », G214 à G220 (`docs/GAPS.md`), `README.md`, `docs/USING_THE_ENGINE.md`, `docs/STATUS.md`, notes `docs/releases/v0.6.2.md`.
- **Site** : pages réécrites « Installer Orosmo » (commande par système, ce que fait l'installeur, installation manuelle, désinstallation), « Créer un projet » (`init`, `build`, `run`, `OROSMO_VERSION`, `update`, `migrate`, `--vendor`), « Compiler avec Make ou CMake » (`orosmo build`, résolution du moteur, bibliothèques du jeu), « Commande orosmo » (toutes les commandes, format JSON) ; nouvelle page « Compiler le moteur » (dépôt) ; tutoriel et boucle d'application sans vcpkg ni `orosmo/` copié.

## Changements incompatibles

- Aucun changement d'API du moteur.
- Projets existants avec `orosmo/` : compilent toujours ; `orosmo migrate` les passe au moteur installé.
- `Generated/` est dans le projet (`ENGINE_GEN_DIR`), plus dans `ENGINE_DIR` ; CMake : `OROSMO_GEN_DIR` = `<build>/orosmo_generated`.
- `make install` d'un projet n'installe plus les dépendances du moteur.
- Linux : glibc ≥ 2.38 (Ubuntu 24.04 et plus récent).

## Commande de démo

```bash
make e2e-init                                   # paquet extrait en lecture seule -> orosmo init -> build sans vcpkg -> lancement
curl -fsSL https://github.com/TimotheSandt/Orosmo/releases/latest/download/install.sh | sh   # après publication
orosmo init mygame && cd mygame && orosmo run
```
