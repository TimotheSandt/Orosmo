# v0.6.2 : distribution du SDK

Version : **`v0.6.2`**. Décision **A76** de l'auteur (2026-11-25, `docs/QUESTIONS.md`), contrat dans `docs/03` §16. Le moteur
lui-même ne change pas (aucun code C++ de `src/` ni `include/` touché) : c'est la façon de l'**installer** et de **construire un
projet** qui change. Le jeu livré aux joueurs ne change pas (liaison statique).

Avant : chaque projet copiait le paquet du moteur dans `orosmo/` et y installait les bibliothèques tierces par vcpkg
(`make install`). Maintenant : un installeur installe une fois les paquets système, l'outil `orosmo` et le moteur précompilé
**avec ses bibliothèques tierces** ; un projet nomme sa version (`OROSMO_VERSION` dans `config.mk`). Ni vcpkg ni `make install`
pour le développeur.

## Ce qui change

| Sujet | Changement | Branche |
| --- | --- | --- |
| Paquet de release | `deps/{include,lib}` : bibliothèques tierces du moteur précompilées, statiques (GLFW, glad, volk, shaderc/glslang/SPIRV-Tools, spirv-cross, FreeType, msdfgen, ktx, meshoptimizer…), licences dans `deps/licenses/` ; fichier `VERSION`. Jamais embarqués : chargeur Vulkan, OpenGL, X11/Wayland, libc (`tools/package-deps.sh`) | `feat/SDK-package` |
| `engine.mk`, `OrosmoConfig.cmake` | dépendances lues dans `ENGINE_DEPS_DIR` (`deps/`, sinon `vcpkg_installed/<triplet>`) ; sortie du compilateur `.cui` dans le **projet** (`Generated/`, `ENGINE_GEN_DIR`) : rien n'écrit dans le moteur | `feat/SDK-package` |
| Gabarit de projet (`apps/demo/Makefile`, `config.mk`) | `OROSMO_VERSION := x.y.z` ; `ENGINE_DIR` résolu par priorité : variable donnée, `orosmo/` local, `orosmo path $(OROSMO_VERSION)`, sinon erreur claire ; vcpkg seulement pour les bibliothèques du jeu (`make add-dep`) | `feat/SDK-package` |
| Outil `orosmo` (`tools/engine-init-rs/`) | moteurs dans `$OROSMO_HOME/engines/<version>` : `install` (vérification `SHA256SUMS`, extraction atomique), `list`, `remove`, `path` ; projets : `init [--vendor]`, `update`, `migrate` ; construction : `build [--release] [--json]`, `run`, `clean` ; `self-update` ; `doctor` sans vcpkg, avec `--fix` | `feat/SDK-tool` |
| `make e2e-init` | paquet extrait **en lecture seule**, contenu contrôlé (`deps/` sans bibliothèque partagée ni chargeur Vulkan), projet compilé **sans vcpkg**, sortie `.cui` dans le projet, `orosmo doctor`, Make et CMake | `feat/SDK-package`, `feat/SDK-tool` |
| Installeurs et release | `install.sh` (Linux, macOS), `install.ps1` (Windows), joints à chaque release avec `SHA256SUMS` ; notes de release sans `make install` | travail parallèle (installeurs, CI) |
| Documentation | A76, `docs/03` §16, G214 à G220, `README.md`, `docs/USING_THE_ENGINE.md`, site (Installer, Créer un projet, Compiler le moteur, Construction, Commande orosmo) | `docs/SDK` |

Intégration : `feat/SDK-integ`.

## Installation

```bash
curl -fsSL https://github.com/TimotheSandt/Orosmo/releases/latest/download/install.sh | sh          # Linux, macOS
irm https://github.com/TimotheSandt/Orosmo/releases/latest/download/install.ps1 | iex              # Windows (PowerShell)
```

Options : `--yes`, `--no-deps`, `--version x.y.z` (avec `curl … | sh` : `| sh -s -- --yes`). Conseillé : télécharger le
script, le lire, puis le lancer.

## Changements incompatibles (par rapport à `v0.6.0`)

- **Aucun changement d'API** du moteur.
- **Projets existants** (moteur copié dans `orosmo/`) : ils compilent toujours (le `Makefile` préfère `orosmo/`). `orosmo migrate`
  les passe au moteur installé ; `orosmo.old/` est gardé si le build échoue.
- **`Generated/`** est maintenant dans le projet (avant : dans `ENGINE_DIR`). Un `Makefile` écrit à la main qui listait
  `$(ENGINE_DIR)/Generated` doit utiliser `$(ENGINE_GEN_DIR)` ; CMake : `OROSMO_GEN_DIR` vaut `<build>/orosmo_generated`.
- **`make install`** d'un projet n'installe plus les dépendances du moteur (elles sont dans `deps/`) ; il installe seulement
  celles du `vcpkg.json` du projet, s'il en a un.
- **Linux** : glibc ≥ 2.39 (Ubuntu 24.04 et plus récent, G217 ; mesuré après la revue : l'outil `orosmo` demande GLIBC_2.39, les archives du paquet GLIBC_2.38).
- `orosmo doctor` ne contrôle plus vcpkg ; nouveaux contrôles « Installed engines » et « Project engine ».

## Ce qui n'est pas prouvé

- **Windows et macOS** : paquet avec `deps/`, outil et installeurs construits par la CI, jamais essayés sur une machine (G216) ;
  macOS : chargeur Vulkan non embarqué, `dlopen` de MoltenVK non vérifié (G215).
- **Installeurs** : écrits en parallèle ; leur exécution de bout en bout (détection du gestionnaire, `PATH`, `orosmo install
  latest`) depuis une vraie release n'est pas couverte par `make e2e-init`, qui part du paquet local (`--package`).
- **`orosmo install` depuis GitHub** (téléchargement, `SHA256SUMS`) : vérifiable seulement après la publication de la release.
- `make e2e-init` rouge tant que G220 n'est pas corrigé ; `orosmo migrate` et `orosmo update` non exercés de bout en bout (tests unitaires seulement).
- Chemins avec espaces (G214) ; moteurs installés non mis en lecture seule, et deuxième build cassé si on les y met (G219) ; paquets natifs et signature reportés (G218).

## Commandes de démo

```bash
make e2e-init                                   # paquet -> extrait en lecture seule -> orosmo init -> build sans vcpkg -> lancement
orosmo init mygame && cd mygame && orosmo run   # après l'installeur
orosmo build --json                             # une ligne JSON par événement
```
