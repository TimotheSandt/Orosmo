# M4 : backend Vulkan

Version : **`v0.4.0`** (`mk/config.mk`, `vcpkg.json`, `Cargo.toml` ×2, extension VS Code). Jalon de `docs/05-PLAN_PAR_JALONS.md`, « M4 · Backend Vulkan ».
Il part de `dev` après M3 bis (`v0.3.1`). Pendant le jalon, l'auteur a recentré le moteur sur un **cœur générique** : le code procédural
est retiré du dépôt (archivé), il reste une seule démo, et le plan est réorganisé (M7 supprimé, M12 et M13 ajoutés ; voir « Décisions »).

## Changements incompatibles (par rapport à `v0.3.1`)

- **API de `platform`** (`include/orosmo/platform/`) : tout est dans `orosmo::platform` ; les fonctions passent en `camelCase`
  (`Init` → `init`, `NewFrame` → `newFrame`, `GetWidthptr` → `getWidthPtr`, `GetWindow` → `getWindow`, `ShouldClose` → `shouldClose`,
  `InputManager::GetInstance` → `getInstance`, etc.) ; les énumérations passent en `kPascalCase` (`WINDOWED` → `kWindowed`, `Normal`
  → `kNormal`) ; `WindowState` est une `enum class`. Comportement inchangé. Un projet créé par `orosmo init` avec `v0.3.1` doit
  renommer ces appels (le modèle fourni est à jour).
- `rhi::createDevice(Backend::kVulkan)` ne renvoie plus `kUnsupported` : il crée un périphérique Vulkan, ou renvoie `kUnsupported` avec
  la raison (pas de chargeur, pas de GPU Vulkan 1.3). `rhi::isBackendCompiled(kVulkan)` est vrai.
- **Dans le dépôt** (pas dans le paquet de release, qui n'avait déjà plus `world` depuis `v0.3.1`) : `orosmo::world`,
  `TerrainRenderer`, `terrain_gen`, `terrain_viewer`, `ui_gallery`, `core_demo`, `rhi_demo` et les cibles `make` correspondantes
  (`viewer`, `terrain-gen`, `terrain-gen-check`, `gallery`, `core-demo`, `rhi-demo`) disparaissent ; `ENGINE_EXTRA_MODULES` n'est plus
  utilisé par la démo. La démo n'a plus d'option `--seed`. `make demo-capture` remplace `viewer-capture` et `gallery-capture`.
- Le paquet de release a une dépendance de plus à la compilation de l'application : `-lvolk` (déjà ajouté à `engine.mk`).

## Ce qui n'est pas prouvé

- **Windows, macOS, Linux arm64** : jamais exécutés pour Vulkan (la CI le dira ; G142). Vulkan sous macOS passe par MoltenVK (M9).
- Un seul GPU (Intel Arc, Mesa ANV) : rien sur NVIDIA ni AMD (G138). Lavapipe vérifié.
- Présentation Vulkan **avec fenêtre** : deux captures seulement ; redimensionnement et synchronisation verticale non vérifiés (G136).
- Barrières conservatrices (G129), une seule file (G130), ressource détruite entre l'enregistrement et `submit` non protégée (G131).
- `make demo-vulkan-check` n'est pas dans `make demo-test` ni dans la CI (G143) ; les scripts de parité n'ont pas de test unitaire (G141).
- Temps GPU par passe non comparables entre OpenGL et Vulkan (G137).
- `clang-format` n'est pas installé sur la machine de développement : `src/rhi/vulkan/` n'est pas formaté (G135).
