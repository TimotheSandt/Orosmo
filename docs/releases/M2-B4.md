# M2 lot B4 : couche de scène sur le RHI (`dev`)

Quatrième sous-lot du lot B de M2 (plan et décision A28 : `docs/05`, `docs/QUESTIONS.md`). Il écrit la **couche de scène** (caméra, lumières, maillage, rendu de scène) sur le RHI et prouve sa **parité** avec le rendu hérité. Comme en B3, ces classes coexistent avec les anciennes : la démo, la capture de référence et le code hérité sont inchangés. M2 n'est pas terminé et **n'est pas proposé à `main`**.

## Écarts au plan, à connaître

Deux changements par rapport au tableau initial de `docs/05` (le tableau est mis à jour) :

- **`Sprite` et `Renderer2D` passent en B5** : ils appartiennent au côté interface (dessin des composants, découpage).
- **`Game` et `World` ne basculent qu'en B6**, avec l'interface : l'ancien et le nouveau runtime graphique ne peuvent pas dessiner dans la même fenêtre, et l'interface (B5) doit être prête pour que la démo présente quoi que ce soit. La preuve de B4 est donc un **test de parité hors écran**, pas une démo à l'écran.

## Ce qui est livré

| Élément | Où |
| --- | --- |
| `Camera` : position, orientation, perspective (formules de l'ancienne), jitter, `CameraData` std140 ; **sans entrées** (G80) | `include/engine/renderer/camera.hpp` |
| `LightManager` / `Light` : 4 types, SSBO std430 vérifié par `static_assert`, tampon qui grandit | `light.hpp` |
| `Mesh` : sommets, index, instances, attributs par tailles, transformation, textures liées, push constants | `mesh.hpp` |
| `FullscreenBlit` : copie plein écran (le RHI n'a pas de blit) | `fullscreen_blit.hpp` |
| Extensions de fin d'image : `IUpscaleMode`, `IAdvancedUpscaleMode`, `IPostProcessPass`, `IFrameGenerationMode`, `BilinearBlitUpscaleMode` | `upscaling.hpp` |
| `SceneRenderer` : cible de scène, groupe de liaison par image, `beginFrame` / `setCamera` / `drawMesh` / `endFrame`, échelle de rendu, jitter de Halton, historique, MRT, profondeur lisible ; remplace `Renderer` + `Renderer3D` avec les mêmes options | `scene_renderer.hpp` |
| Shaders en GLSL 450 : éclairage identique à l'ancien, blit | `shaders/rhi/` |

Un changement de comportement voulu : la scène est **toujours** dessinée dans sa propre cible puis copiée vers la destination (1:1 sans échelle) ; l'ancien « rendu direct à l'écran » disparaît, donc plus de profondeur sur le framebuffer par défaut. Sans échelle et avec le mode « disabled », une copie 1:1 de repli est faite.

## Preuve de parité

`tests/renderer/parity_tests.cpp` reconstruit le terrain de la démo (graine 1, grille 500×500, bruit fractal) sans passer par l'ancien `Mesh`, le dessine avec les réglages de `Game::init` / `World::Init` (caméra en (0, 1, 0), FOV 75°, ambiante 0,2, directionnelle (2, −3, 0,5)), et compare la couleur de la cible de scène à `docs/BASELINE/reference/scene-opengl-seed1-1280x720.png`.

- **Intel Arc (machine de la référence)** : **0 pixel d'écart à la tolérance 0** (identique octet pour octet).
- Test de non-régression : tolérance de 4 par canal et au plus 0,1 % de pixels au-delà, pour un autre pilote (llvmpipe en CI, G30).
- **Pas couvert** : `ui.png` (interface et texte : B5/B6).

## Limites connues (voir `docs/GAPS.md`, G80 à G83)

- `Camera::Inputs` non porté : le pilotage revient à l'application (G80). Constantes de shader brutes, pas par nom (G81). Ponctuelles et projecteurs non rendus (G82). Tests dépendants du dossier courant `apps/demo` ; shaders `shaders/rhi/` pas encore dans le paquet du moteur (G83).
- Windows et macOS : le code compile (CI) mais les tests GPU ne s'y exécutent pas (G67).

## Commande de démo

```bash
make demo-test                                              # 290 cas
apps/demo/bin/tests/tests -ts="renderer/parity"             # parité avec l'image de référence (terrain graine 1, 1280x720)
apps/demo/bin/tests/tests -ts="renderer*"                   # toute la couche de ressources et de scène
make rhi-demo RHI_DEMO_ARGS="--out /chemin/image.png"       # démo du lot A, toujours valable
```

En cas d'écart, le test écrit l'image obtenue dans `$TMPDIR/engine_scene_parity_actual.png`.
